| 字段 | 值 |
|------|-----|
| 模块名 | AI Coding |
| 版本 | 0.2 |
| 状态 | 全新模块 |
| 相关文件 | `src/ai/ai.ts`, `src/ai/providers/`, `src/ai/bridge/`, `src/components/ChatPanel.tsx`, `src/components/DiffReviewPanel.tsx`, `src/hooks/useInlineCompletion.ts`, `src/hooks/useBridgeWS.ts` |

---

## 1. 职责概述

本模块提供两条正交的 AI 能力通道，均受 `dataConsentGiven` 门控：

| 通道 | 触发方式 | 网络路径 | 延迟目标 |
|------|---------|---------|---------|
| 内联补全（Ghost Text） | 防抖 300ms / ⌥/ | 设备直连模型 API | < 2s |
| 对话式 plan-execute | ChatPanel 输入 | iPad → Bridge WS → Agent | 无硬性要求 |

iOS 沙盒约束：无本地进程执行，所有代码执行发生在远端 Bridge；写盘始终在 iPad 本地完成。

## 2. 安全门控

```
用户操作 / 自动触发
        │
        ▼
  dataConsentGiven? ──── false ──→ 抛出错误，终止，不发送任何内容
        │
       true
        │
        ▼
   读取 Keychain key
        │
        ▼
   发送请求 / 建立 WS
```

**Keychain Key 名称（expo-secure-store）：**

| Provider | Key 名称 |
|----------|---------|
| Claude | `ipad_vscode_ai_key_claude` |
| OpenAI | `ipad_vscode_ai_key_openai` |
| GLM | `ipad_vscode_ai_key_glm` |
| Bridge Token | `ipad_vscode_bridge_token` |

规则：
- `dataConsentGiven` 为 `false` 时，`ai.ts` 立即抛出错误，不进行任何网络请求。
- Provider API Key 和 Bridge Token 不得出现在日志、UI 展示或错误消息中。
- Bridge Token 仅注入 WebSocket `Authorization` header，不存入内存缓存以外的位置。

## 3. 内联补全（Ghost Text）

### 3.1 数据流

```
Monaco onDidChangeModelContent
        │
        ▼
  debounce(300ms)  ◄──── 或 ⌥/ 手动触发（立即）
        │
        ▼
  buildFIMRequest()
  ┌─────────────────────────────────┐
  │ prefix: 光标前文本（≤3000 tok） │
  │ suffix: 光标后文本（≤500 tok）  │
  │ language: Monaco language ID    │
  │ maxTokens: 64                   │
  └─────────────────────────────────┘
        │
        ▼
  dataConsentGiven? ── false → throw Error
        │
       true
        │
        ▼
  AbortController.signal
        │
        ▼
  AIProvider.requestInlineCompletion(req, signal)
        │                    │
        │ (5s timeout)       │
        ▼                    ▼
  completion text      timeout/abort
        │                    │
        ▼                    ▼
  offset 是否仍匹配？    静默丢弃
  ── 不匹配 → 静默丢弃
        │
      匹配
        │
        ▼
  Monaco setGhostText(completion)
```

### 3.2 TypeScript 类型定义

```typescript
type FIMRequest = {
  prefix: string    // 光标前内容，最多 3000 tokens
  suffix: string    // 光标后内容，最多 500 tokens
  language: string  // Monaco 语言 ID，例如 "typescript"
  maxTokens: 64     // 固定值，短补全减少延迟
}

interface AIProvider {
  id: 'claude' | 'openai' | 'glm'
  requestInlineCompletion(req: FIMRequest, signal: AbortSignal): Promise<string>
}
```

### 3.3 Provider 适配器

#### Claude（无原生 FIM → Messages API）

```
POST https://api.anthropic.com/v1/messages
Headers: x-api-key: <ipad_vscode_ai_key_claude>

Prompt 格式（Human/Assistant turn）:
  Human: Complete the code. Output ONLY the completion between prefix and suffix, no explanation.
  Prefix: {{prefix}}
  Suffix: {{suffix}}
  Assistant:

默认模型: claude-haiku-4-5
```

#### OpenAI → Completions API

```
POST https://api.openai.com/v1/completions
Headers: Authorization: Bearer <ipad_vscode_ai_key_openai>

Body:
{
  "model": "gpt-4o-mini",   // 默认值
  "prompt": "{{prefix}}",
  "suffix": "{{suffix}}",
  "max_tokens": 64,
  "stop": ["\n\n"]
}
```

#### GLM → Chat Completions（FIM 同 Claude prompt 格式）

```
POST https://open.bigmodel.cn/api/paas/v4/chat/completions
Headers: Authorization: Bearer <ipad_vscode_ai_key_glm>

Prompt 格式: 同 Claude Messages prompt 格式（Human/Assistant turn）
默认模型: glm-4-flash
```

### 3.4 默认模型

| Provider | 默认模型 |
|----------|---------|
| Claude | `claude-haiku-4-5` |
| OpenAI | `gpt-4o-mini` |
| GLM | `glm-4-flash` |

用户可在 Settings → AI → 内联补全模型 中覆盖。

### 3.5 交互行为

| 操作 | 效果 |
|------|------|
| Tab | 接受全部 ghost text |
| ⌥→（Option + 右箭头） | 逐词接受 ghost text |
| Esc | 拒绝，同时 abort 当前请求 |
| 继续输入任意字符 | 拒绝，abort 当前请求，重新触发防抖 |

### 3.6 取消与超时

```
触发新输入 / Esc
      │
      ▼
AbortController.abort()   ←── 复用同一 controller 实例，新请求前 replace
      │
      ▼
fetch 被取消，Promise reject with AbortError → 静默处理

超时机制:
  setTimeout(5000, () => controller.abort())
  5 秒无响应 → abort → 不显示 ghost text，不报错
```

过期建议：补全返回时校验当前光标 offset，若 offset 已变化则静默丢弃（不调用 setGhostText）。

## 4. 对话式 plan-execute

### 4.1 整体流程

```
用户在 ChatPanel 输入 prompt
        │
        ▼
buildPlanRequest() → plan_request 消息
        │
        ▼
Bridge WebSocket（已建连）
        │
  ┌─────┴──────────────────────────┐
  │          Bridge 端             │
  │  Agent（Claude Code/Codex/GLM）│
  │  生成 plan，流式返回思考内容   │
  └─────┬──────────────────────────┘
        │
        ▼
  plan_thinking（多次，流式）
  → ChatPanel 实时渲染 Thinking 内容
        │
        ▼
  plan_response { diffs: DiffPlan }
        │
        ▼
  DiffReviewPanel 内嵌于消息流中
  用户逐文件审阅：批准 / 拒绝
        │
   全部审阅完
        │
        ▼
  用户点"执行"
        │
        ▼
  execute_request { approved: true }
        │
        ▼
  execute_progress（多次）→ 进度 UI
        │
        ▼
  execute_complete { appliedFiles }
        │
        ▼
  iPad 本地 applyDiffs()
        │
        ▼
  refreshFileTree() + refreshGitStatus()
  refreshAffectedTabs(affectedPaths)
```

### 4.2 Bridge WebSocket 消息协议

#### iPad → Bridge

```typescript
// 发起规划请求
{
  type: 'plan_request'
  prompt: string
  context: {
    currentFile: string        // 当前打开文件的相对路径
    selection: string          // 当前选区文本（无选区时为空字符串）
    workspaceTree: string      // 文件树摘要（文本格式）
    recentFiles: string[]      // 最近访问文件列表
  }
  sessionId: string            // UUID，本次会话标识
}

// 确认执行
{
  type: 'execute_request'
  sessionId: string
  approved: true
}

// 取消会话
{
  type: 'cancel'
  sessionId: string
}
```

#### Bridge → iPad

```typescript
// 流式思考内容（多次）
{ type: 'plan_thinking'; content: string }

// 最终计划（一次）
{ type: 'plan_response'; diffs: DiffPlan }

// 执行进度（多次）
{ type: 'execute_progress'; file: string; done: number; total: number }

// 执行完成（一次）
{ type: 'execute_complete'; appliedFiles: string[] }

// 错误
{ type: 'error'; message: string; code: string }
```

### 4.3 DiffPlan 类型定义

```typescript
type DiffPlan = {
  description: string   // 本次变更的整体描述（一句话）
  diffs: Array<{
    file: string        // 相对于 workspace 根的路径，例如 "src/utils/foo.ts"
    action: 'create' | 'modify' | 'delete'
    before: string      // 文件原始内容（delete/modify 时有值；create 时为空字符串）
    after: string       // 修改后内容（delete 时为空字符串）
    unified: string     // unified diff 格式字符串，供 DiffReviewPanel 渲染
  }>
}
```

### 4.4 applyDiffs 实现

```typescript
async function applyDiffs(diffs: DiffPlan['diffs']): Promise<void> {
  for (const d of diffs) {
    const absPath = workspaceRoot + '/' + d.file
    if (d.action === 'delete') {
      await deleteItem(absPath)
    } else {
      // 'create' 和 'modify' 均写入 d.after
      await writeFile(absPath, d.after)
    }
  }
  await refreshFileTree()
  await refreshGitStatus()
  refreshAffectedTabs(diffs.map(d => workspaceRoot + '/' + d.file))
}
```

调用时机：收到 `execute_complete` 后立即调用，Bridge 不直接写盘。

### 4.5 会话状态机

```
IDLE
 │  用户发送 prompt
 ▼
PLANNING ── plan_thinking → 流式更新 ChatPanel
 │  收到 plan_response
 ▼
REVIEWING ── 用户逐文件审阅（批准/拒绝）
 │  用户点"执行"
 ▼
EXECUTING ── execute_progress → 进度 UI
 │  收到 execute_complete
 ▼
APPLYING ── applyDiffs() 本地写盘
 │  完成
 ▼
IDLE

任意状态 ── 用户取消 / 收到 error → IDLE
```

## 5. Bridge WebSocket 连接管理

### 5.1 建连条件

满足以下全部条件时，应用启动后自动建立 WS 连接：
1. `aiConfig.enableChat === true`
2. `aiConfig.bridgeEndpoint` 已配置（非空）
3. Bridge Token 在 Keychain 中存在（`ipad_vscode_bridge_token`）

### 5.2 认证

```
WebSocket 握手 headers:
  Authorization: Bearer <bridge_token_from_keychain>

bridge_token 仅用于 header 注入，不写日志，不传给 UI 层。
```

### 5.3 重连策略

```
连接断开
    │
    ▼
指数退避重连:
  尝试 1: 等待 1s
  尝试 2: 等待 2s
  尝试 3: 等待 4s
  尝试 4: 等待 8s
  尝试 n: min(2^(n-1) * 1000ms, 30000ms)

上限: 30s 间隔
无最大重试次数限制（持续重试直到成功）
```

### 5.4 后台管理

```
App 切入后台
    │
    ▼
启动 5 分钟计时器
    │
    ├── 5 分钟内回前台 → 取消计时器，保持连接
    │
    └── 超过 5 分钟 → 主动关闭 WS（避免 iOS 后台网络限制）
              │
              ▼
         App 回前台 → 触发重连流程
```

## 6. ChatPanel UI 规格

### 6.1 消息结构

```typescript
type ChatMessage = {
  id: string
  role: 'user' | 'assistant' | 'system'
  content: string
  timestamp: number
  // assistant 消息专属
  thinkingContent?: string     // 累积的 plan_thinking 文本
  diffPlan?: DiffPlan          // plan_response 内容
  tokenUsage?: {
    inputTokens: number
    outputTokens: number
  }
}
```

### 6.2 Thinking 状态渲染

- 收到 `plan_thinking` 时，向当前 assistant 消息追加 `content` 到 `thinkingContent`。
- 展示为可折叠的"思考中..."区块，带旋转动画（spinner）。
- 收到 `plan_response` 后，thinking 区块折叠（保留可展开）。

### 6.3 DiffReviewPanel（内嵌，非模态）

```
┌──────────────────────────────────────────────┐
│ 变更计划：<description>                       │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ src/utils/foo.ts  [modify]   ✓ 批准      │ │
│ │ ── before/after unified diff ──          │ │
│ │ @@ -1,5 +1,7 @@                         │ │
│ │  ...                                    │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ src/new_file.ts   [create]   ✗ 拒绝      │ │
│ │ ── unified diff ──                       │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│  [全部批准]        [执行已批准的变更]          │
│                                              │
│  输入 tokens: 1,234  输出 tokens: 456        │
└──────────────────────────────────────────────┘
```

规格：
- 每个文件 diff 独立展开/折叠，默认展开。
- 批准/拒绝状态存储在本地（不发给 Bridge），仅影响 `execute_request` 发送哪些文件。
- "执行"按钮在至少一个文件被批准时可点击。
- 被拒绝的文件不写入 `applyDiffs`（过滤后传入）。
- token 用量估计显示在 DiffReviewPanel 底部（数值来自 `plan_response` 或本地估算）。

## 7. 错误处理

| 场景 | 处理方式 |
|------|---------|
| `dataConsentGiven = false` | 抛出 `AIConsentError`，UI 提示需要开启数据同意 |
| Keychain 读取失败 | 抛出 `AIKeyNotFoundError`，UI 提示配置 API Key |
| 内联补全超时（5s） | 静默丢弃，不显示 ghost text，不报错 |
| 内联补全 HTTP 错误 | 静默丢弃（不打断编辑流） |
| Bridge WS 断开 | UI 状态栏显示"Bridge 断开"，按指数退避重连 |
| Bridge `error` 消息 | ChatPanel 显示 `error.message`，会话回到 IDLE |
| `applyDiffs` 写盘失败 | Toast 报错，部分写入的文件不回滚（v0.2 限制） |
| plan-execute 切后台中断 | 会话挂起，回前台后显示"会话已中断"提示 |

## 8. 已知限制（v0.2）

1. **Bridge 自建门槛高**：Bridge 服务需用户自行部署并配置端点，无官方托管服务。

2. **内联补全无离线模式**：所有内联补全均需访问云端 API，无设备端本地模型支持。

3. **plan-execute 后台中断风险**：iOS 后台网络限制导致 plan-execute 长任务切后台后可能中断；v0.2 无断点续传机制。

4. **不支持二进制文件变更**：Bridge 仅返回文本 diff，二进制文件（图片、字体等）无法通过 plan-execute 变更。

5. **超大仓库上下文截断**：`workspaceTree` 和 `recentFiles` 上下文受模型 context window 限制，超大仓库需截断，可能导致 Agent 规划不完整。

6. **applyDiffs 无原子性**：写盘逐文件串行执行，中途失败不回滚已写入文件（依赖 Git 恢复）。

7. **Claude 无原生 FIM 支持**：Claude 通过 Messages API 模拟 FIM，质量和延迟略逊于 OpenAI 原生 `/v1/completions`。
